## 0. 总体结论

**评级：有条件通过（需修订后复审）**

计划方向正确、结构完整、门禁意识良好（0-CLS / LCP / AA / reduced-motion / Axe 均被提及），且对仓库现状有基本认知（`astro-public`、`--max-width-wide`、`site-header.ts` 24px 阈值等均命中真实代码）。但存在 **3 个 P0 阻断项**（与计划自设门禁直接冲突）与 **7 个 P1 高优项**（对比度硬指标失实、焦点指示不达标、信息架构回退等）。核心问题集中在：资产与 LCP 门禁自相矛盾、Hero 颜色契约未定义（主题串用风险）、声称的对比度数字不可复现。

## 1. 维度一：视觉保真度（Visual Fidelity）

### 1.1 【P0】Hero 颜色契约缺失 → 双主题下必然出现不可读状态

- 新 Hero =「暗蒙版 + 白字」，但新令牌是 `html[data-theme]` 双主题。计划未规定 Hero 内文字绑定哪套令牌。
- **实测**：亮色模式 `--color-text-primary: #1c1917` 叠在暗蒙版（65% × 中调壁纸复合 `#262935`）上，对比度 **1.21:1**——完全不可读。暗色模式 `#f8fafc` 为 13.8:1。
- **结论**：Hero 必须声明独立颜色契约（Hero 作用域内固定暗色令牌组，或 `data-theme="dark"` 固定 + Hero 专用令牌作用域），并在 §4.3 写明；否则亮色主题下首页首屏直接报废。

### 1.2 【P1】信息架构回退：CTA 与标签链接被静默删除

- 现状 Hero（`Hero.astro`）含 4 个 CTA（探索文章 / 分类图谱 / 全站归档 / 关于博主）与 6 个真实标签链接（`buildTagPath` 映射，含「生成式超分辨率」「信号与系统」）。
- 新 Hero 仅 4 个**纯文本** chips（`# 流匹配与扩散模型`…），无 `<a>`/href/路径映射；CTA 全部消失，「关于博主」入口从首页移除。
- 计划全文无「删除清单 / 删除理由 / 替代入口」章节——对齐目标图二（Ayeez 风格）不能以删除现有导航能力为代价且不做说明。chips 若保留链接，需给出 label→tag 映射（注意「深度学习理论」→ 实际 tag「深度学习」的现状差异）。

### 1.3 【P2】「黄金分割定位」与多断点裁切断言缺乏证据

- `background-position: center 25%` 并非黄金分割（0.618），是上部聚焦位（用词错误）；更关键：4K 图在 9:16 竖屏 cover 下水平方向裁切约 **68% 宽度**，人物水平位置若偏离画面中心即被裁掉。「人物居中且视线聚焦点自然」在各断点（16:9/16:10/4:3/9:16）是未经验证的断言。
- **建议**：提供各断点 cover 裁切预览（或按人物实际坐标反推 object-position 响应式值），并核实壁纸人物/焦点区实际像素位置（建议直接从 `3840x2160px_D_suisen.png` 采样验证 25%~35% 区域内容）。

### 1.4 【P2】渐变标题实现与「辉光」目标相悖

- `-webkit-text-fill-color: transparent` + `text-shadow`：阴影从透明字形中透出，形成字内糊影而非外部辉光；应使用 `filter: drop-shadow()`。同时需补标准属性 `background-clip: text`，并在 `forced-colors: active` 下回退实色文字（否则 Windows 高对比度下标题整体消失）。

### 1.5 【P2】蒙版底部与正文区背景存在接缝风险

- 蒙版底端 = `0.98×#0a0c16 + 2%壁纸` ≈ `#0a0c16` 系；正文区若用 `--color-bg-base: #0f1221`，Hero 与 `#latest-posts` 之间出现可感知的暗色阶差。计划未定义 Hero→正文的过渡规则（统一 canvas 背景或透明渐变桥接）。

### 1.6 【P3】资产许可

- 壁纸为《ディメンション凸ラバース!!》豪华版特典，公开站点使用许可/出处标注未评估（非技术但应登记）。

## 2. 维度二：设计令牌（Design Tokens）

### 2.1 【P0】对比度声称全部无法复现，且文档内部互相矛盾

| 声称位置                    | 声称值 | 实测值                                 | 判定                   |
| --------------------------- | ------ | -------------------------------------- | ---------------------- |
| §2.1 `#C2410C` on `#fdfbf7` | 5.2:1  | **5.01:1**（纯白 5.18:1）              | 数字失实               |
| §2.2 / §5.1 同上            | 5.4:1  | 5.01:1                                 | 与 §2.1 自相矛盾且失实 |
| §2.2 `#4338CA` on `#fdfbf7` | 7.2:1  | 7.65:1                                 | 接近，略偏差           |
| §5.1 白字 on 蒙版           | 14.5:1 | 9.5~16.9:1（随壁纸亮度、蒙版深度波动） | 不可复现，无采样前提   |
| §5.1 金色大字 on 蒙版       | 9.8:1  | 7.6~13.4:1                             | 不可复现，无采样前提   |

- **结论**：计划把「硬指标」建立在无计算依据的数字上。修订时必须：a) 统一并重算所有声称值；b) 对蒙版上文字给出**最坏情况采样点**（壁纸最高光区如逆光金辉处的像素亮度 + 对应蒙版 alpha）并给出计算过程；c) 渐变文字按**最差端**（珊瑚橙 `#FF6B4A`，65% 蒙版亮区实测最低 3.54:1，仅大字 3:1 勉强达标）评估，不能按高光端 `#FDE047` 声称。

### 2.2 【P1】Focus 指示令牌不满足 WCAG 2.2 2.4.13（及 1.4.11）

- `--color-focus-ring: rgba(245,158,11,0.45)` 在 `#0f1221` 上复合后实测 **2.62:1 < 3:1**；
- 亮色 `rgba(194,65,12,0.35)` 在 `#fdfbf7` 上复合后实测 **1.69:1**，严重不达标。
- §5.1 声称「2px 实线夕阳金」（`--color-focus: #f59e0b`，8.66:1 达标）与 §2.2 保留的 0.45 alpha ring 令牌自相矛盾。修订：ring 令牌改实色或 ≥0.6 alpha，并明确组件 box-shadow 焦点统一走该令牌。

### 2.3 【P1】亮色模式内联代码文字不可读

- `--color-code-inline-text: #9a3412` on `--color-code-bg: #1c1917` 实测 **2.39:1**（暗色模式 `#fbbf24` 11.52:1 正常）。亮色 code 块为深底，文字必须用亮色系（如 `#fdba74` / `#fbbf24` 级）。

### 2.4 【P1】`--color-text-dim` 与亮色 `--color-accent-coral` 文字对比不足

- `#64748b` on `#0f1221` 实测 **3.91:1 < 4.5:1**；且现有 `home.css`（pagination-link L179）正在用它——若沿用到正文级内容即违规。需在令牌文档中标注 usage 约束（仅占位符/禁用态/装饰），或调亮至 ≥4.5:1。
- 亮色 `#ea580c`（coral）on `#fdfbf7` 实测 **3.44:1**，仅适合大字/UI 态；且「珊瑚」语义在亮色主题漂移为橙红（建议亮色保持珊瑚橙 `#e25822` 系并单独验算）。

### 2.5 【P1】`--color-accent-cyan` 兼容别名语义错误 + 静默改色面未登记

- 计划把 `--color-accent-cyan` 重定向为靛紫 `#818cf8`：现存引用面包括 `prose.css`（≥7 处：链接、数学块、行内码）、`AmbientBackground`（glow-orb-cyan）、`ReadingProgress`、`Hero` 等——全部会被静默从青色变成紫色，视觉变化未在任何章节声明。
- 需补「旧令牌 → 新令牌迁移映射表 + 逐组件审查清单」；`--color-accent-purple` 被删除但未登记（实测全仓无引用，删除安全，但仍应入表）。建议：要么弃用 cyan 别名并逐组件替换为语义名（secondary/indigo），要么保留真青色 `#00e5ff` 为 tertiary 强调色并在计划中说明其取舍。

### 2.6 【P2】内部不一致三处

1. §4.3「3.5rem 夕阳金与暮紫环境网格」vs 令牌 `--color-ambient-grid: #1c223a`（暗蓝灰，非金非紫）；
2. §4.2「边框呈微光暮紫」vs `--color-border-accent: #f59e0b`（金）；「暮紫」仅存在于 `--color-accent-secondary`；
3. §2.1 的 5.2:1 vs §2.2/§5.1 的 5.4:1（见 2.1）。

### 2.7 【P2】`color-scheme` 缺失（现状亦缺，计划未补）

- 无 `color-scheme: dark` / `light` 声明 → 暗色主题下原生表单控件、日期选择器、系统滚动条仍为 UA 亮色。应在 `html[data-theme]` 上成对声明。

### 2.8 【P3】亮色 `--color-surface-overlay` 与 `--color-surface-base` 同为 `#ffffff`，弹层/浮层无层级区分（需以阴影补足或拉开色阶）。

## 3. 维度三：组件架构（Component Architecture）

### 3.1 【P0】4K PNG 资产策略与 LCP ≤2.5s 门禁直接冲突

- 3840×2160 PNG 壁纸（此类特典壁纸通常 8~20MB）直接作为 `background-image` + 无条件 `<link rel="preload">`：
  1. `background-image` 无法利用 `<img>` 的 `fetchpriority` / `decoding` / `srcset`，LCP 计时不可控；
  2. preload 放在 `BaseLayout.astro` head = **全站每页**（文章页/归档页/搜索页）都预载 4K 图，非首页流量浪费且与文章内容抢带宽；
  3. 移动端 9:16 视口实际渲染宽度约 750px，4K 资源 90% 以上是浪费。
- **修订方向**：Layer 1 改用 `<img>`（`object-fit: cover; object-position: 25% center` 响应式）+ AVIF/WebP 三档 `srcset`（约 1080p / 2K / 4K）+ `eager fetchpriority=high` + 仅首页条件输出 preload；容器底色兜底防 CLS（计划此点正确，保留）。

### 3.2 【P1】BaseLayout 改造方案未收敛，且现状描述不准确

- 计划称「BaseLayout.astro 将 slot 包裹在限制 max-width 的 main 中」——实际约束在 `global.css` 的 `main` 规则（L136–142：`max-width: var(--max-width-wide); padding: 2rem 1.25rem 4rem`），`BaseLayout.astro` 本身无此逻辑。方案设计应基于此修正后的认知。
- 「增加全宽首屏槽位**或**类名条件控制」二选一未收敛；`isHome` prop 的 Props 接口/类型变更未写；结构示意中 `<Hero slot="hero">` 的接收端 `<slot name="hero">` 与 main 的宽度/内边距解耦方式未展示。
- **建议**：收敛为「named slot 置于 `<main>` 之外 + `isHome` 仅控制 head 级资源与 skip-link 契约」，并给出 `BaseLayout.astro` 修改后的完整骨架。

### 3.3 【P1】AmbientBackground 方案缺失（范围声明了，正文没有）

- §0/路线图阶段 2 声明适配 AmbientBackground，但正文零细节。且存在两个未定义交互：
  1. `glow-orb-cyan` 使用 `--color-accent-cyan`（将被重定向为靛紫）→ 光球变色；
  2. AmbientBackground 是 `position: fixed; z-index: -1` 全屏层，Hero 不透明壁纸会将其**完全遮蔽**——「Hero Layer 3 网格」与全站网格层的关系（去重？叠加？Hero 区域是否禁用全站层？）必须定义。

### 3.4 【P1】SiteHeader：现状机制已具备，增量被高估；透明态文字对比未验

- `site-header.ts` 已实现 24px 阈值 + rAF 节流 + `data-header-state` expanded/compact 契约（计划 §4.2 描述的滚动收敛机制**已存在**），真正增量仅「首页首屏透明态样式」。
- 透明态（顶部 0.4 alpha 蒙版区）上，若导航文字沿用 `--color-text-muted: #94a3b8`，壁纸高光处实测约 3~4:1，不达标；glass 态（0.75 alpha）下亮金内容上 muted 文字实测 **4.36:1** 也低于 4.5:1。首页 Header 需专用文字令牌（secondary 级）与「透明态/玻璃态」两套对比验证。

### 3.5 【P1】锚点滚动无焦点管理

- `<a href="#latest-posts">` 纯锚点：键盘用户触发后焦点仍留在箭头链接上，无 `:target` 样式或目标 `tabindex="-1"`。现状 skip-link 基线（`#main-content` + `tabindex="-1"`）良好，但计划 §5.1 将目标改写为 `#latest-posts` 与现状契约冲突——需明确 skip-link 目标与 Hero 是否纳入跳过范围（建议保留跳 `#main-content`，Hero 属装饰性区域）。

### 3.6 【P2】Hero 组件规模失控风险

- 现状 `Hero.astro` 已 597 行（>200 行红线），计划继续堆叠 4 背景层 + 标题块 + 引言 + chips + 滚动指示器。建议拆分为 `HeroBackdrop`（Layer1-3）/ `HeroContent`（标题/引言/chips）/ `ScrollIndicator`。

### 3.7 【P2】质量门禁缺视觉回归与性能预算断言

- 现状 tests 仅 7 个 spec，**无** `toHaveScreenshot`/snapshot 类视觉回归。对「视觉保真度重构」应加入 Playwright 截图 diff（暗/亮 × 桌面/移动 × reduced-motion × forced-colors），并在门禁中加入 LCP/CLS 预算断言（web-vitals 或 Playwright 性能指标）。

### 3.8 【P3】细节项

- 滚动指示器 24px 命中区处于 WCAG 2.2 AA 2.5.8（24px 下限）边缘，建议 44px 命中区；
- `min-height: 100svh` 写法未定（桌面 100vh 与移动 100svh 的语法收敛建议直接 `100svh` + 兜底）；
- 摘要「320px~4K」vs §5.2 断点从 360px 起，320px 无策略（现状 Hero 有 25rem 断点，勿回退）；
- §3.1「在 public/images/ 同步备份」与 `astro.config.ts` 注释「与 Hexo 的 public/ 完全隔离」（`publicDir: "astro-public"`）冲突，备份动作应删除或改为 dist 产物说明；
- 亮色 `--color-surface-overlay` 与 base 同色（见 2.8）；
- §5.2 4K 与 ≥1440px 合并断点，3.2rem 对 4K 视口偏小，建议 4K 单独档位。
